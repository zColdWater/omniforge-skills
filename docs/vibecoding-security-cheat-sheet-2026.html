CRITICAL CVE-2025-48757

1. Lock Supabase Row-Level Security (RLS) on Every Public Table

Top failure across Lovable, Bolt.new & Cursor Supabase MVPs

AI builders frequently create public tables without ENABLE ROW LEVEL SECURITY or leave permissive USING (true) policies, letting anyone with your public anon key dump every user row via PostgREST.

Audit every CREATE TABLE statement in supabase/migrations/. For every table in the public schema storing user data, add ALTER TABLE public.<table> ENABLE ROW LEVEL SECURITY; ALTER TABLE public.<table> FORCE ROW LEVEL SECURITY; REVOKE ALL ON TABLE public.<table> FROM anon; and add owner-scoped SELECT/INSERT/UPDATE/DELETE policies checking auth.uid() = user_id. Show the exact SQL migration diff.
CRITICAL 52 SECRET PATTERNS

2. Purge Hardcoded Keys from NEXT_PUBLIC_* and VITE_* Client Chunks

VibeShield checks 24 full JS bundles (up to 2.5MB each)

Anything prefixed NEXT_PUBLIC_ or VITE_ is compiled verbatim into browser JavaScript. OpenAI, Anthropic, Stripe secret, Resend, or Supabase service_role keys get scraped in minutes.

Search the entire codebase for NEXT_PUBLIC_, VITE_, sk_live_, sk-proj-, sk-ant-, sb_secret_, service_role, and hardcoded database URIs. Move all third-party API calls requiring secret keys into authenticated server-side API routes or Edge Functions, rotate any exposed env var names, and confirm zero secret keys remain in client-imported files.
CRITICAL CVE-2025-29927

3. Patch Next.js Middleware Auth Bypass & Disable Source Maps

Affects unpatched Next.js <15.2.3 / <14.2.25 / <13.5.9 / <12.3.5

An external x-middleware-subrequest header can skip middleware auth guards on vulnerable versions. Meanwhile, exposed .js.map files leak your entire TypeScript source tree.

Check package.json and upgrade next to a patched release (>=15.2.3 or >=14.2.25) to remediate CVE-2025-29927. In next.config.mjs / next.config.ts, explicitly set poweredByHeader: false and productionBrowserSourceMaps: false. Also enforce server-side session verification inside every Server Action and Route Handler instead of relying solely on middleware.
CRITICAL RTDB / FIRESTORE

4. Replace Test-Mode Firebase Rules with Default-Deny Auth Rules

Public /.json?shallow=true & Firestore document reads checked passively

Default Firebase test-mode rules allow global read/write until an expiry date that founders forget to tighten before launch.

Review firestore.rules and database.rules.json. Replace any allow read, write: if true or timestamp-based test rules with a default deny rule (match /{document=**} { allow read, write: if false; }) and explicit per-collection rules requiring request.auth != null && request.auth.uid == resource.data.userId.
HIGH OBSERVATORY A+

5. Ship Strict CSP, HSTS, COOP & Permissions-Policy Headers

2026 N=60 Benchmark: 46.7% ship zero CSP; 28.3% score Grade F

100% of audited indie SaaS apps ran TLS 1.3, yet 85% lacked strict CSP and 81.7% missed Cross-Origin-Opener-Policy, leaving apps open to XSS and clickjacking.

Add Mozilla Observatory A+ HTTP security headers (Strict-Transport-Security with includeSubDomains, Content-Security-Policy without unsafe-eval, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: strict-origin-when-cross-origin, Cross-Origin-Opener-Policy: same-origin, and Permissions-Policy) to next.config.mjs or vercel.json, plus publish /.well-known/security.txt (RFC 9116).
HIGH 28 PROBES

6. Block Exposed /.env, /.git, GraphQL Introspection & Open Redirects

Single misconfigured static rule exposes secrets or schema maps

Self-hosted Docker, Nginx, and misconfigured static hosts frequently serve .env, .git/HEAD, /swagger.json, or allow ?next=https://evil.com redirects.

Verify .dockerignore, .gitignore, and web server rules block /.env*, /.git/*, /backup.sql, and /swagger.json in production. Disable GraphQL introspection when NODE_ENV === 'production', and validate all login redirect/next query parameters against a strict relative-path allowlist starting with a single /.
HIGH RFC 7208 / 7489

7. Flatten SPF Under 10 Lookups & Enforce DMARC Beyond p=none

2026 N=120 Benchmark: 71.7% of indie SaaS lack enforced DMARC

Exceeding 10 recursive SPF lookups triggers PermError and lands onboarding/reset emails in spam; p=none lets attackers spoof your brand domain.

Audit my sending services (Google Workspace, Resend, Postmark, Stripe, etc.) and produce a single v=spf1 TXT record strictly under 10 DNS lookups, confirm 2048-bit DKIM alignment for each ESP, and provide a staged DMARC rollout plan from p=quarantine to p=reject with rua= reporting plus MTA-STS.
MEDIUM LLMS.TXT / GEO

8. Publish /llms.txt, /llms-full.txt & Validated Schema.org @graph

2026 N=50 Benchmark: Only 22% ship /llms-full.txt; avg Schema 35.6/100

AI answer engines (ChatGPT Search, Perplexity, Claude) skip client-only SPA skeletons and cite sites with clean Markdown specs and verified Schema.org entities.

Create /public/llms.txt (H1, concise blockquote, grouped doc/pricing links) and /public/llms-full.txt (complete factual product & pricing reference), verify /robots.txt allows OAI-SearchBot, PerplexityBot, and ClaudeBot, and add validated Organization + WebSite + SoftwareApplication + FAQPage JSON-LD in the root layout.
